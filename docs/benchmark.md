# The fpsdet benchmark

Generated by `fpsdet benchmark report` from the committed artifacts (fpsdet.benchmark/1). Do not edit by hand: change the artifacts, then regenerate.

## What this benchmark can prove

- That the committed numbers follow from the committed artifacts: every evaluation, strength estimate, split and result verifies by digest, and its statistics recompute, without re-scoring anything.
- That fpsdet's decisions on the published TF2 and CS2 runs follow from the prepared inputs: the same events, labels, cohort and profile give the same cases, packets, eligibility, evaluation and strength, on Python 3.11 and 3.12.
- That the prepared inputs follow from the downloaded sources by the frozen selection: the converters rebuild them byte for byte from the same downloads.
- That every native detector trips on a behaviour planted for it and stays quiet on an honest twin, and that the challenge and external-signature protocols behave as documented, in controlled synthetic fixtures.
- Exactly what changed when anything moves: inputs, labels, selection code, profile, cohort, detector code, decisions, findings, eligibility, statistics, strength or only presentation.

## What this benchmark cannot prove

- How well fpsdet detects cheating in general. Each real dataset is one population with someone else's labels: RGL's bans and the CS2CD authors' judgement, neither of them ground truth.
- Anything about a detector a dataset cannot observe. On TF2 and CS2 most detectors are not observable at all; that is a gap in the data, not a zero.
- That synthetic fixtures resemble real cheats. They are planted by construction and qualify code, never a rate.
- That fpsdet is better or worse than any other system. Nothing else is evaluated here.
- That TF2 can be rebuilt by a third party with the same player ids: its pseudonym key never leaves the curator's machine, and the RGL ban list and logs.tf match lists change over time. A third party gets an exact report of what differs.

There is no overall score. Each section answers its own question, and a detector a dataset cannot observe is shown as not observable, never as zero.

**TF2 league matches with RGL ban labels** (`tf2-rgl-v1`).
- Source: [logs.tf](https://logs.tf): match logs that TF2 community servers upload: each player's shots and hits per weapon, sniper headshots, and kills per minute; [RGL](https://rgl.gg): the competitive league's public ban list, with a reason for each ban. Fetched 2026-10-04. RGL's ban list grows and its reasons can be edited, and a player's logs.tf match list grows with every match, so a later fetch selects different matches; an uploaded log does not change. prepare reports a different download as INPUT_CHANGED.
- Licence and use: Neither site publishes terms for its data. logs.tf's robots.txt asks crawlers to stay off its API, so the fetcher asks for a bounded sample, one or two requests at a time with a pause after each, names this project in its User-Agent, and caches every response. Nothing downloaded is committed: no log, ban, SteamID, name or match id. Only pseudonymous per-player evaluation rows and aggregate numbers are. Data: logs.tf match logs and RGL's public bans. Not affiliated with Valve, logs.tf or RGL.
- Pseudonyms: Each SteamID becomes tf- and the first 10 hex digits of its HMAC-SHA256 under a 32-byte key the converter creates on the curator's machine (pseudonym.key). The key never leaves it, so published results name nobody. A rebuild with another key gets other ids, and another half of the never-banned players builds the baseline; the key commitment below lets it say so exactly.
- Selection, frozen (`fpsdet.benchmark-selection/tf2-rgl/1`): Labelled accounts: RGL accounts banned for cheating (not for assisting, distributing or developing cheats) with at least 20 team matches on logs.tf before the ban; their 20 latest team matches before the ban. Comparison: everyone in those lobbies RGL never banned, with at least 8 matches in the fetched logs, plus 150 never-banned players per half with their own 20 latest team matches. Equal evidence: every player keeps at most their 20 latest matches; a banned account's only before its ban. A team match has 12 or more players. Only aimed, hitscan weapons are converted. A fixed bit of each pseudonym sends never-banned players to the baseline or to be scored, so nobody is judged against a baseline that includes them.
- Counts: downloaded logs 10,218, events 4,139,445, scored players 2,764, baseline players 1,566; labelled cheater 228, not banned 2,158, other ban 1,184, vac 20.

**CS2 matchmaking (CS2CD) with the dataset authors' labels** (`cs2cd-v1`).
- Source: [CS2CD on Hugging Face](https://huggingface.co/datasets/CS2CD/CS2CD.Counter-Strike_2_Cheat_Detection): 795 CS2 matchmaking matches parsed from server-recorded demos, with the authors' cheater labels. Fetched 2026-10-04. The fetcher does not pin a dataset revision. If the authors publish a new one, a later fetch can differ; prepare reports it as INPUT_CHANGED. The cached tick tables are rewritten by pyarrow, so only the event files, which the converter writes deterministically, are part of the source identity.
- Licence and use: CS2CD is published under CC BY 4.0. Nothing downloaded is committed. Per-player evaluation rows with the converter's match-local ids, and aggregate numbers, are. Data: CS2CD by its authors, CC BY 4.0. Not affiliated with Valve or with the dataset's authors.
- Pseudonyms: CS2CD names players Player_N within each match; the converter writes them as <match>-p<N> (nc047-p9). There is no key, so a rebuild gets the same ids. A player cannot be followed across matches.
- Selection, frozen (`fpsdet.benchmark-selection/cs2cd/1`): Matches: the first 180 no-cheater and the first 120 with-cheater matches by number, keeping complete ones (13 rounds or more). Baseline: the first 120 complete no-cheater matches, screened for whole lobbies of outliers by fpsdet baseline --screen-matches. Their players are never scored. Scored: the other 45 complete no-cheater matches (unreviewed) and the 108 complete with-cheater matches (hand-labelled cheaters and hand-reviewed players). Every player is one match.
- Counts: matches fetched 300, complete matches 273, events 4,071,829, scored players 1,529, baseline players 887; labelled cheater 504, clean, reviewed match 576, clean, unreviewed match 1,649.

## 10. Known blind spots

- An assist that copies human timing, human noise and human lag.
- An aim assist tuned to stay inside the best humans measured: past every human is a finding, better than average is not.
- A reader that follows each challenge only briefly, only in the last second of its window, or only beside an enemy the client can see.
- A cheat that waits out the interpolation delay.
- A capture-card aimbot looking at pixels.
- A DMA read of the frame the game actually drew.
- A wallhack that never aims at a hidden enemy.
- Shared positions acted on no faster than a voice could carry them, or shared by a player who is not in review.
- Anything a game's telemetry cannot show. In the benchmark's real data, 17 of 22 detectors on TF2 and 15 of 22 detectors on CS2 are not observable at all, which is not the same as finding nothing.
- A number with too few humans behind it: a detector waits for a thick enough baseline, and says so, before it compares.
- A server that labels a visible enemy as hidden manufactures cases. That is an emitter bug, and the docs call it out field by field.
- External records are read unsigned by default, and a verified signature proves who signed a record, not that its finding is true.

## 11. Reproduce it

Everything below runs from a clone of the repository with standard-library Python 3.11 or 3.12. The CS2 converter also needs `pip install -r examples/cs2/requirements.txt`; the external-signature scenarios need `pip install 'fpsdet[auth]'`.

```bash
# Check every committed artifact, offline, without scoring (what CI runs):
PYTHONPATH=src python -m fpsdet benchmark verify
# Rebuild and qualify every controlled fixture and scenario (seconds, no data):
PYTHONPATH=src python -m fpsdet benchmark run --dataset synthetic
# Real data: download the public sources (network, rate-limited), rebuild the inputs (offline), run (offline):
PYTHONPATH=src python -m fpsdet benchmark fetch --dataset cs2 --data ~/fpsdet-data/cs2 --python <a Python with the CS2 requirements>
PYTHONPATH=src python -m fpsdet benchmark prepare --dataset cs2 --data ~/fpsdet-data/cs2 --python <the same>
PYTHONPATH=src python -m fpsdet benchmark run --dataset cs2 --data cs2=~/fpsdet-data/cs2
# Or every dataset whose prepared data is on this machine:
PYTHONPATH=src python -m fpsdet benchmark run --all --data tf2=~/fpsdet-data/tf2 --data cs2=~/fpsdet-data/cs2
```

Each run prints MATCH, ENVIRONMENT_ONLY, PROVENANCE_ONLY, PRESENTATION_ONLY, DRIFT, INPUT_CHANGED or NOT_RUN per dataset, with the categories that explain it, and writes `result.json` with every artifact beside it. After `prepare`, everything runs offline. A full real-data run reads millions of events and is not part of ordinary CI; `benchmark verify` and the synthetic run are.

## Third-party systems

Nothing but fpsdet is evaluated here. A future version can evaluate another system on the same frozen populations without forcing it into fpsdet's schema. It would take one neutral record per subject:

```json
{"format": "fpsdet.benchmark-submission/1", "dataset": "tf2-rgl-v1", "subject": "tf-0a1b2c3d4e", "decision": "flag | no_flag | abstain", "observation_kinds": ["optional, the system's own names"], "confidence": null}
```

It would be scored with the same label semantics, splits, eligibility rules (abstain is not a miss) and intervals, and never folded into one number. Not implemented: the immediate goal is that fpsdet itself can be reproduced and checked.
