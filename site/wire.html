The server writes one line.

Emit from the dedicated server, at the moment it accepts the shot or the movement sample, using the server's hit and the server's clock. One JSON object per line. Do not have the client POST its own stats. This does not end cheating.

What you send decides what can fire

Start with the fields you already compute. Each rung adds checks and changes nothing under it. Leave a field out and its check stays quiet. It never guesses. Rung 2 adds no new case at all. It is there so a stim or a legal mod never becomes one.

  1. Rung 1

    Day one

    The fields that already move the body.

    • weapon_id
    • t_ms
    • speed_mps
    • on_ground
    • loadout_weight_kg
    • displacement_cause
    • recoil_pitch_deg
    • spray_index

    Turns on

    • Speed over the cap
    • Fire rate under the cycle
    • A metronome on a legal cycle
    • No kick under the floor

  2. Rung 2

    + the server’s own caps

    Send the number the server used, not a table.

    • expected_max_ground_speed_mps
    • expected_min_recoil_pitch_deg
    • mod_set

    Turns on

    • Stims, perks, slides, and legal mods stay clean

  3. Rung 3

    + the kick and the pull

    Both numbers, on the same tick.

    • applied_recoil_pitch_deg
    • compensation_pitch_deg

    Turns on

    • Same-tick mirror
    • The same leftover on two accounts

  4. Rung 4

    + what this client could know

    Queries the server already runs.

    • information_state
    • hidden_track_ms
    • private_track_ms
    • challenge_id
    • challenge_track_ms
    • challenge_vision_state
    • challenge_audio_state
    • enemy_id
    • party_id

    Turns on

    • Tracking a hidden mover
    • Quiet only while unknowable
    • Aim on a private replay, or a planned challenge
    • A teammate before a voice

  5. Rung 5

    + the two positions

    Error to the snapshot, error to the picture, and the delay.

    • wire_error_deg
    • picture_error_deg
    • interp_delay_ms

    Turns on

    • The picture is late

  6. Rung 6

    + enough humans

    A thick cohort per rank and weapon, and your own numbers.

    • hit
    • hitbox
    • distance_m
    • extra_metrics

    Turns on

    • Past the best measured human
    • Past the rank, inside the humans
    • An account that changed
    • Your number. No code change.

Required on every line

game_id, match_id, player_id, t_ms, and a rank (skill_band, or skill_prior). event_type defaults to shot. player_id should be a stable pseudonym. Keep the map from pseudonym to account on your side.

Send the cap and the recoil floor the server already used. Omit a field you cannot measure. A guessed number false-flags. A missing number is skipped.

applied_recoil_pitch_deg is the kick the server applied. compensation_pitch_deg is the signed view command on that same tick. Negative is a pull-down. Omit either one and the mirror check does nothing. Send spray_index with them: in a game with a fixed spray pattern, the pattern is removed before the check, because practiced players pull it on time.

information_state is visible, audio, or unknowable. Unknowable means this client's own line-of-sight and audio queries both failed. Audio is knowable: footsteps and a legal callout have to be labeled, or a quiet aim on a heard target becomes a radar case. Labeling a visible enemy as unknowable manufactures the case.

hidden_track_ms is time, since this player's previous shot, on a mover this client could neither see nor hear. Shots labeled audio do not count, and neither do shots within a second of since_perceived_ms, the time since this client last saw or heard that enemy. private_track_ms is time on a replay of someone else's movement, placed where this client could not see or hear it. Omit either field, or send 0, when you do not have that query. A bad query manufactures the case. How those bars fire is on Scoring.

A planned challenge goes on every event of its player while its window is open, shot or movement: challenge_id from the plan, challenge_track_ms on the probe since the previous event, and the server's own verdict on the probe for that moment in challenge_vision_state and challenge_audio_state: absent, known, or unchecked. The plan comes from fpsdet challenge plan and the server secret, which never goes in an event or a profile. Challenge reviews are experimental and not production-qualified. The reference Godot server writes all four (docs/pilot.md).

wire_error_deg is the angular error to the snapshot the server just sent. picture_error_deg is the angular error to the position the official client is drawing. interp_delay_ms is that delay. The sample above is closer to the picture than to the wire, which is what a person does. Omit any of the three when you cannot measure it. view_delta_deg is not this pair. A comparison against the wrong timeline manufactures the case.

through_geometry is the server trace, not the client's claim. hitbox is head, upper_torso, lower_torso, limbs, or omitted on a miss.

Movement

Send movement on a fixed cadence. Ten hertz is enough. A speedhack between shots is invisible if you only sample on the trigger.

{
  "game_id": "your-game",
  "match_id": "m-1001",
  "player_id": "stable-pseudonym",
  "t_ms": 19000,
  "event_type": "movement",
  "skill_band": "average",
  "loadout_weight_kg": 14.2,
  "speed_mps": 5.5,
  "expected_max_ground_speed_mps": 6.1,
  "on_ground": true,
  "displacement_cause": "none"
}

When a grenade, a vehicle, a parachute, a ladder, a zipline, an ability, or an admin teleport moves the body, set displacement_cause for every sample in that window. If you do not know, send unknown. Unknown is dropped. A long untagged throw can look like a speedhack, and the case will say the server did not mark a cause. Only none on the ground is scored.

Where the script runs

Unity.

A dedicated-server script, not a client MonoBehaviour. examples/unity/BaselineEmitter.cs writes a line. Ship the lines to your collector.

Unreal.

From the server GameMode, after the server confirms the hit, post lag-compensation rewind, and only when HasAuthority() is true.

Godot.

The dedicated-server peer only. JSON.stringify one object. on_ground is the server body's floor state. expected_max_ground_speed_mps is the cap that server already applied. A complete reference server, with vision and audio queries and a live challenge, is examples/pilot/godot.

Per-title fields, including what not to copy out of a community table, are on Games.

The collector

Appending lines to a file is enough for a solo dev. fpsdet ingest partitions them into lake/game=<id>/dt=<YYYY-MM-DD>/events.ndjson. A studio can point the same stream at a bus it already runs. The scorer does not care how the line arrived.

Call run_score in-process if you would rather not shell out. Pass a cohort built from an earlier window. The lake, the queue, and the optional brief are on Source.

from fpsdet.parse import load_profile, parse_event
from fpsdet.pipeline import run_score

profile = load_profile("profiles/example-loadout.json")
events = [parse_event(obj) for obj in batch]
cases = run_score(events, profile, cohort, history, reports)
