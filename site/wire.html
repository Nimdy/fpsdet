Wire a game

The server writes one line.

Emit from the dedicated server, at the moment it accepts the shot or the movement sample, using the server's hit and the server's clock. One JSON object per line. Do not have the client POST its own stats. This does not end cheating.

Required on every line

game_id, match_id, player_id, t_ms, and a rank (skill_band, or skill_prior). event_type defaults to shot. player_id should be a stable pseudonym. Keep the map from pseudonym to account on your side.

Send the cap and the recoil floor the server already used. Omit a field you cannot measure. A guessed number false-flags. A missing number is skipped.

Shot

{
  "game_id": "your-game",
  "match_id": "m-1001",
  "player_id": "stable-pseudonym",
  "t_ms": 18420,
  "utc": "2026-10-02T18:04:11Z",
  "event_type": "shot",
  "skill_band": "average",
  "weapon_id": "ak-74",
  "mod_set": ["compensator", "vertical_grip"],
  "hit": true,
  "hitbox": "head",
  "distance_m": 42.5,
  "through_geometry": false,
  "spray_index": 6,
  "recoil_pitch_deg": 1.4,
  "expected_min_recoil_pitch_deg": 1.1,
  "applied_recoil_pitch_deg": 1.8,
  "compensation_pitch_deg": -0.4,
  "hidden_track_ms": 0,
  "private_track_ms": 0,
  "wire_error_deg": 1.8,
  "picture_error_deg": 0.4,
  "interp_delay_ms": 100,
  "information_state": "visible",
  "aim_jitter_deg": 0.42,
  "enemy_id": "enemy-4",
  "loadout_weight_kg": 14.2,
  "on_ground": true,
  "speed_mps": 5.4,
  "expected_max_ground_speed_mps": 6.1,
  "displacement_cause": "none"
}

applied_recoil_pitch_deg is the kick the server applied. compensation_pitch_deg is the signed view command on that same tick. Negative is a pull-down. Omit either one and the mirror check does nothing.

information_state is visible, audio, or unknowable. Unknowable means this client's own line-of-sight and audio queries both failed. Audio is knowable: footsteps and a legal callout have to be labeled, or a quiet aim on a heard target becomes a radar case. Labeling a visible enemy as unknowable manufactures the case.

hidden_track_ms is time on a mover the server had not made visible. private_track_ms is time on a replay of someone else's movement, placed where this client could not see or hear it. Omit either field, or send 0, when you do not have that query. A bad query manufactures the case. How those bars fire is on Scoring.

wire_error_deg is the angular error to the snapshot the server just sent. picture_error_deg is the angular error to the position the official client is drawing. interp_delay_ms is that delay. The sample above is closer to the picture than to the wire, which is what a person does. Omit any of the three when you cannot measure it. view_delta_deg is not this pair. A comparison against the wrong timeline manufactures the case.

through_geometry is the server trace, not the client's claim. hitbox is head, upper_torso, lower_torso, limbs, or omitted on a miss.

Movement

Send movement on a fixed cadence. Ten hertz is enough. A speedhack between shots is invisible if you only sample on the trigger.

{
  "game_id": "your-game",
  "match_id": "m-1001",
  "player_id": "stable-pseudonym",
  "t_ms": 19000,
  "event_type": "movement",
  "skill_band": "average",
  "loadout_weight_kg": 14.2,
  "speed_mps": 5.5,
  "expected_max_ground_speed_mps": 6.1,
  "on_ground": true,
  "displacement_cause": "none"
}

When a grenade, a vehicle, a parachute, a ladder, a zipline, an ability, or an admin teleport moves the body, set displacement_cause for every sample in that window. If you do not know, send unknown. Unknown is dropped. A long untagged throw can look like a speedhack, and the case will say the server did not mark a cause. Only none on the ground is scored.

Where the script runs

Unity. A dedicated-server script, not a client MonoBehaviour. examples/unity/BaselineEmitter.cs writes a line. Ship the lines to your collector.

Unreal. From the server GameMode, after the server confirms the hit, post lag-compensation rewind, and only when HasAuthority() is true.

Godot. The dedicated-server peer only. JSON.stringify one object. on_ground is the server body's floor state. expected_max_ground_speed_mps is the cap that server already applied.

Per-title fields, including what not to copy out of a community table, are on Games.

The collector

Appending lines to a file is enough for a solo dev. fpsdet ingest partitions them into lake/game=<id>/dt=<YYYY-MM-DD>/events.ndjson. A studio can point the same stream at a bus it already runs. The scorer does not care how the line arrived.

Call run_score in-process if you would rather not shell out. Pass a cohort built from an earlier window. The lake, the queue, and the optional brief are on Source.

from fpsdet.parse import load_profile, parse_event
from fpsdet.pipeline import run_score

profile = load_profile("profiles/example-loadout.json")
events = [parse_event(obj) for obj in batch]
cases = run_score(events, profile, cohort, history, reports)
