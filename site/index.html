Run the test before you wire a game.

You are looking at an answer key, and the program that grades it. Thirty-two fake players. A known decision on each one. fpsdet reads JSON a dedicated server already can write, and it writes a case a person opens. It does not install on a player’s PC. It does not ban. This does not end cheating.

From the repo, Python 3.11 or newer. No packages to install.

PYTHONPATH=src python3 -m fpsdet demo

The reason says the explosion sample was excluded. One fast sample is not a case. A case needs a sustained run. That refusal is what you want on a short log.

Why the server

The cheat left the PC. Its commands did not.

A kernel driver watches processes on the player’s PC. A DMA card, a second PC, or a capture card runs the cheat where that driver never runs. Every move and every shot still has to be accepted by the dedicated server. fpsdet reads what the server accepted, beside what the server already knew.

The planted pairs

Same numbers. Opposite answers.

Most of the desk is pairs. One player is cheating. The other has the same speed, the same hits, or the same quiet aim, and is not. A detector that cannot tell them apart bans the wrong one. The middle of each row is what they share. The ends are the one fact that differs. Each end opens that case on the desk.

What will fire

Four checks. The first two are ordinary, and they work. The third catches a body the official client never drew. The fourth is two positions of a player they can see. None of them ban anyone. Each one is drawn on Scoring.

Gear the server already applied.

A 10 kg kit sprinting at 7.1 m/s when that server’s cap for the kit is 5.6. The same speed, tagged as a blast, is not a case. Fire rate uses the gun’s own cycle. Recoil uses the floor for that build. This is not a new idea. It catches blatant speed, a macro under the legal gap, and a stock gun with no kick. A cheat that stays inside the cap, and jitters its timing by a few milliseconds, walks through it.

The clock.

The camera is allowed to kick. The case is the player command matching the kick the server just applied, backwards, on that same tick. Pull the same kick one shot later and it stays clean. In a game with a fixed spray pattern, a player who memorised it pulls on time too, so the pattern is removed first and only the part of the kick that changes between sprays is tested. This catches a same-tick no-recoil script. A script that waits one shot and adds a little noise stays quiet. Your server has to log both numbers, applied_recoil_pitch_deg and compensation_pitch_deg. If you do not have them, this check does nothing.

A fact this client was not sent.

Sustained aim on an enemy this client could neither see nor hear (footsteps count as heard, and so does a body that broke line of sight a moment ago), or on a replay of someone else’s real movement, turned onto another heading, where this client has no sight and no audio. There is no invisible flag. The official client drops that body before draw because it is occluded. A snapshot parser that keeps every player still sees a person running. Sustained aim on it is a review. A four-shot clip of it stays clean.

That third check can catch a cheat that aims at bodies in the server snapshot. It cannot catch a DMA read of the frame the game actually drew, or a capture card looking at pixels. Those never receive a body the official client did not draw. If the visibility query is wrong, the case is manufactured. Fix the query before you trust the case.

The server can plan each replay with a secret, so no one can predict the next one, and count a moment only when its own checks say the body was unseen and unheard. One caution, measured: in a machine dry run, a stand-in holding a doorway's edge still, over a probe that barely moved behind it, reached the same bar. Until people have played the pilot, a replay review is a file to open, not a verdict. What was found.

The picture is late.

Every moving player has two positions. The wire is the snapshot the server just sent. The picture is where the official client draws them, the wire position from one interpolation delay ago. A person aims at the picture. A packet aimbot aims at the wire, often the tick the snapshot arrives. The case is not “too accurate.” Both crosshairs can hit. The case is the error to the wire staying smaller than the error to the picture, across enough shots, before that delay has elapsed. Standing still makes the two positions match, and nothing fires. One shot does not fire. On the desk, wire-lock is the review and picture-track is clean.

That check still misses a capture card looking at the pixels that were drawn, a cheat that reimplements the official interpolator and waits out the delay, and a server that compares against the wrong timeline. A wrong timeline frames a legal player. A listen server can forge the fields. If you cannot measure the two errors and the delay, omit them. The check does nothing.

How it runs

One line in. A case out. A person decides.

  1. 1

    The server writes a line

    {"speed_mps": 7.1, …}

    Per shot and per movement sample, from the server’s own accept path.

  2. 2

    The lake keeps it

    game=…/dt=…/events.ndjson

    Append-only files you own. A folder for a solo dev, an object store for a studio.

  3. 3

    Humans set the bar

    rank × weapon × build

    Once you have players. Until then, the gear rules run alone.

  4. 4

    The scorer counts

    gear · clock · knowledge · picture · humans

    A count, not a model call. Reports move the queue, never the score.

  5. 5

    A case is written

    case.json · case.html · packet

    Review, watch, clean, or held, with the reasons, the numbers behind them, and what produced them.

  6. 6

    A person decides

    automated_action: none

    Wire your ban button to your review tool, after a person looks. Never to the word review.

ReportsJump the scan queue, clean numbers included. They never add to the score.

AI brief, optionalAny OpenAI-compatible endpoint writes a paragraph on a case. It cannot change the decision.

features.csvTrain your own model on reviewer labels. Keep the gear rules beside it.

DashboardsGrafana, Elastic, or Splunk read the case JSON. They are viewers, not the detector.

Under the decision

Every case says what made it.

The sentence a reviewer reads is the top of the case. Under it sits the same finding as data, and enough to check it without trusting whoever handed it over. The evidence, in full.

Findings, knowledge, provenance.

Each finding as a record, what this client could have known (unchecked is never absent), which checks could run at all, and digests of the code, the game settings, the baseline and the events. One packet digest binds them. The same inputs give the same packet.

Challenges, planned with a secret.

The server plans each probe from a secret that never leaves it. The plan holds ids, windows and commitments. The code is public, and the next probe still cannot be predicted. A probe the client could see or hear voids itself.

Other systems, kept in their place.

Records from client anti-cheat, platforms or leagues ride along as given, signed or not. They can make a watch. However many agree, they never make a review. A verified signature says who sent a record, not that it is true.

Controlled fixturesAll 22 checks trip on a planted behaviour and stay quiet on its honest twin. That qualifies code. It is never a rate.

Public real dataTF2 and CS2, rebuilt from public sources by anyone, checked by digest from download to published table.

Live pilotOne challenge, run in a Godot dedicated server with stock clients. All 8 declared scenarios came out as declared, and every capture scored the same offline.

Human pilotDesigned and pre-registered: consenting adults, playing honestly with probes running. No person has played yet.

What you set up on the server

Nothing on the player’s machine. When the dedicated server accepts a shot or a movement sample, append one JSON object. Start with the fields you already compute to move the body.

  • loadout_weight_kg, speed_mps, on_ground
  • expected_max_ground_speed_mps — the cap that server used, after the pen, the stance, and the perks
  • displacement_cause — none on a real sprint. explosion, vehicle, parachute, ability for the whole throw. unknown is dropped, not flagged

Score the file with the same command as the example, pointed at your log and your profile. Legal play comes back clean or insufficient_data. A sustained sprint over the cap you sent comes back review. Stop there. Do not wire a ban to that word. automated_action is none so a hasty integration has to notice it.

Add the clock only when you can send the applied kick and the view command. Add the hidden-aim and replay checks only when line-of-sight and audio for that connection are queries you already trust. Add the wire-and-picture check only when the server can measure angular error to the snapshot it just sent, angular error to the position the official client is drawing, and the interpolation delay. Omit any of the three and that shot does not count. Which field turns on which check is drawn on Wire a game, with the JSON, Unity, Unreal, and Godot shapes. Tarkov, Call of Duty, Battlefield, and WARDOGS are the same fields, on Games. The bars are on Scoring.

What you have to lose

An afternoon, and a log line. Cheaters are in every shooter tonight, with a kernel driver and without one. Running the planted test takes nobody off a server.

ZeroBandwidth wrote this. No studio is running it. There is no deployment to trust. Reproduce the two decisions above, then try to break them.

  • If a legal slide, a legal mod, or a stim would have been a case, send the cap your server already used.
  • If you can sit on the private replay and stay clean, the rule is wrong.
  • If you can sit on the wire, ahead of the picture, and stay clean, the rule is wrong.
  • If the terminal does not print weight-cheat as review and blasted as clean, do not wire anything.

What still gets through

An aim that never sits on a hidden mover, never sits on the replay, aims at the picture rather than the wire, and does not get quieter when that mover exists.

Aim that stays on the picture the official client draws, including a cheat that waits out the interpolation delay. Standing still, where the snapshot and the picture are the same place.

A DMA read of the frame the game actually drew, and a capture card looking at pixels.

A server that scores aim against a position that client was not shown. That manufactures the case.

A humanizer with its own noise, when that noise also matches human lag and human variance. A callout slow enough to have been a voice. A speed pulse inside the glitch filter. A kick that barely changes from shot to shot. Stamps that all land on one tick. A gun the server itself fired.

A listen server, or a game that lets the client decide the hit, can forge every field. The contract is a dedicated server. A bad visibility query manufactures the case. Fix the query.

A reader that follows each challenge only briefly, only in the last second of its window, or only beside an enemy the client can see.

Anything your telemetry cannot show. On TF2 and CS2 match totals most checks cannot run at all. That is a gap in the data, not a finding of nothing.

A record from another system that is wrong. Unsigned records are read by default, and a verified one is only known to come from its provider's key.
