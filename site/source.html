The reference is the Python in this repo.

fpsdet 0.4.0. Python 3.11 or newer. No runtime dependencies; checking providers' signatures on external records is the one optional extra. A solo dev and a studio run the same contract. A port in another language matches when it reproduces the planted demo and tests/test_fpsdet.py. This does not end cheating.

Run the planted matches

PYTHONPATH=src python3 -m fpsdet demo
PYTHONPATH=src python3 -m unittest tests.test_fpsdet
PYTHONPATH=src python3 -m fpsdet benchmark verify
PYTHONPATH=src python3 -m fpsdet pages

demo writes demo/board.html. That page starts with a six-step walk-through, then the thirty-two planted players. The first tape is the 10 kg sprint beside the blast. benchmark verify checks every published result against its committed artifacts by digest, offline, without scoring. pages writes a folder a static host can serve: these pages, and a fresh desk beside them. Nothing in that command publishes the repository.

The repository is github.com/Nimdy/fpsdet. These HTML pages are the walk-through. The same contract, written for an implementer, is docs/scoring.md, docs/integration.md, docs/games.md, and docs/operations.md. The evidence a case carries is docs/observations.md, docs/provenance.md and docs/challenges.md; what has been tested is docs/benchmark.md.

Where the bytes go

fpsdet ingest appends each line to lake/game=<id>/dt=<day>/events.ndjson. That tree is enough for a solo dev. A studio can put the same objects in the object store it already uses and aggregate with DuckDB or ClickHouse. The case a reviewer opens is small. The shots that built it do not belong in a search index as the system of record.

Reports are a queue, not a verdict. Scan reported players first, including the clean ones. A person reads review, then watch, then clean. Two batch tells, a shared leftover and a teammate who swings before a voice, are watches. They do not become reviews.

A brief, if you want one

--ai calls one chat completion per case that is a review, a watch, or reported. The endpoint is any server that speaks the OpenAI chat-completions shape. Set FPSDET_AI_BASE_URL, FPSDET_AI_MODEL, and FPSDET_AI_API_KEY when the server checks one. Every player id the case mentions, including other accounts named by the batch checks, is replaced with an alias, and party ids, match ids, and the seal are removed before the request. The model is told not to recommend a ban and not to invent numbers. If the endpoint is down, the decision already exists. The brief cannot change it.

features.csv is for a later model trained on your reviewers' labels. Keep the gear rules beside it. A learned score that can talk a sustained over-cap sprint out of a case has learned the wrong objective.

Before other people send patches

fpsdet is under the PolyForm Small Business License 1.0.0. Under 100 people and US$1M revenue, build on it and ship it. Past that, ask ZeroBandwidth for a commercial license. There is no contributor agreement yet. Add one before you take contributions. Patches that describe how to build a cheat, or that weaken the innocence rules so a blast becomes a ban, are off the point of this repo. Patches that add a game's server-side fields, a profile, or a failing test for a false positive are the point.

Store a pseudonym. Do not collect raw mouse input, kernel memory, or a hardware id here. Those are a different product. Wire a ban action to your own review tool after a person looks. Do not wire it to decision == review.

What still gets through is part of the contract. A DMA read of the drawn frame, a capture card, a cheat that waits out the interpolation delay, a wrong timeline, and a listen server are named there on purpose.
